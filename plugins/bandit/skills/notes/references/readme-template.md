## 🤖 For agents

1. **Start here.** This page lists every project, recent meeting, open request and reference
   note with a one-line summary. Pick notes by summary; open only those.
2. **Frontmatter first.** Every note starts with YAML: `type`, `status`, `domain`, `summary`,
   `created`, `updated`, plus `project` (a link to the project hub), `related`, `board-task`
   when they apply. Read it before the body.
3. **Links:** `[[name]]` is a filename, unique in this domain. Resolve it with
   `nc_webdav_find_by_name(pattern="name.md", scope="MyNotes/{Domain}")`. Never link to or
   from another domain.
4. **Cite** notes as `[[name]]` when you use them.
5. **Writing:** new notes go to `_inbox/` only, as new files, following the `bandit-notes` skill.
   Never edit an existing note in `_inbox/`: it's Leo's working space until he reviews it.
   `Claude/` holds settings, not content. `_archive/` holds finished notes.
6. **Status** is the note's lifecycle, not the work state: the task board owns work, linked
   by `board-task`.

## 📐 Conventions (summary)

- **Filenames:** kebab-case. Dated notes `{slug}-YYYY-MM-DD.md`, evergreen `{slug}.md`. Unique
  across the vault, so `[[links]]` survive moves.
- **Status:** `inbox → triaged → active → waiting → done`. Done notes move to `_archive/`
  (path mirrored, `archived-from` stamped). The task board tracks the work; notes link it via
  `board-task`.
- **Frontmatter:** `type`, `status`, `domain`, `summary`, `created`, `updated`, plus `project`,
  `source`, `board-task`, `related`, `file-to` when they apply. Lists in block style.
- **Attachments** live in `_attachments/` and stay there when notes move.
- **The inbox is Leo's.** Nothing there is edited until he reviews it with `/bandit-notes file`.
- **Moves happen only after confirmation.** `Claude/` holds settings only; skills live in
  `MyNotes/_skills/`.
- The full rules live in the `bandit-notes` skill. To change a convention, change the skill.

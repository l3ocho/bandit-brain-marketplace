# Changelog

All three plugins (`bandit`, `bandit-dev`, `bandit-maker`) and the marketplace share one version, following [Semantic Versioning](https://semver.org): **major** when a command, mode or skill is removed or renamed or the Project Context format changes, **minor** for a new command, mode, skill or behaviour, **patch** for fixes and wording. Entries group changes as Added, Changed and Fixed, in the spirit of [Keep a Changelog](https://keepachangelog.com). `scripts/release.py` cuts a release: it dates the `Unreleased` entry, bumps every version and tags `vX.Y.Z` on `main`; each tag becomes a [GitHub release](https://github.com/l3ocho/bandit-brain-marketplace/releases).

## Unreleased

Version 2.0.0 when released: the Project Context format changes and commands are removed (card BM-15).

### Removed
- **The MyNotes vault as a notes storage.** `bandit:notes` keeps one storage, the app's Notes. Gone with it: the commands `/bandit:notes init`, `home` and `settings`, the vault conventions (folders, filenames, frontmatter, Obsidian settings) and the WebDAV write rules. The naming rules that lived in the vault file are now conventions §4, as note titles.
- **Minutes start from a transcript** (Changed, not removed: listed here with its pair). `bandit:minutes` takes a transcript named, attached or waiting in the folder the project's instructions name, and writes the minutes from it, unattended when nobody is there to answer; a handled transcript moves to that folder's `done/`. Transcribing a recording in the chat is the fallback, announced with its expected time.
- **Saving minutes to a file-storage folder.** `bandit:minutes` saves its minutes as notes, or hands them over in the chat; the options "same folder as the audio" and "another BanditCloud folder" are gone.

- **The settings folder, the second copy for another surface and the dev mirror.** `bandit:project` no longer keeps a project's instructions and reference doc in a vault folder, no longer builds a Claude Code copy of Claude.ai instructions (or the reverse), and no longer installs a Stop hook that copies a repository's settings out. Gone with them: the commands `/bandit:project sync` and `update`, the settings line at the top of the instructions, and checker rule DM1.
- **The working-folder manifest is no longer uploaded.** The guard writes it in `.claude/` and prints its counts; nothing asks for an upload.

- **Audit rules S5, S7, S8, S10 and S11.** They compared the files of the settings folder and the second copy of a project's instructions, which no longer exist. Their numbers are not reused. Snapshots of schema 1 to 7 no longer load: `check_structure.py` refuses one by name, and its report is superseded.

- **The sprint helper's vault branches** (BM-15). A sprint's papers are notes on the project's board only, its sprint data file sits in `.sprint/`, and closing archives the papers by status; the papers-folder link, the folder move to the archive and the vault's write rule are gone. Checker rule SP4, which checked a vault note's frontmatter, is retired.

### Added
- **A project can be limited to a subfolder, and to some boards or columns** (BM-16). The Project Context's `domain:` may name a subfolder as a path, `{top} / {sub}`, so a client's agent sees and changes only its client's folder. A new optional `write:` line names the boards, and columns, a project may write on, while it still reads its whole domain: an agent that shares a board with others writes only in its own column. The board and notes helpers refuse any other write; the structure audit scores a nested domain, checks the `write:` line, and now counts boards in folders at any depth.
- **One page of hard rules** (BM-16). `bandit:tasks references/hard-rules.md` states, one order per line, the rules every skill follows on every write: names, tool limits, field limits, and what goes in a description, a note, a comment or a sub-task, each naming where its detail lives. Every skill's Never section points to it; checker rule HR1 keeps it so.
- **A wave's shell output and its search agent are counted** (BM-T7). The wave report's Flow block says how many times the wave launched the search agent, and its Tokens block how much shell output the wave chat took in, against the 501,000-character baseline. A wave with no search agent, or over the target, is named in the report's lessons.
- **Checker rule VO1** (BM-15): no shipped file names the MyNotes vault, WebDAV, a vault settings path or the vault's archive folder, except a line saying what was retired.
- **A project checks in with a stamp.** `/bandit:audit check`, run inside a project, writes one section of the note `{domain}-audit-stamps` on the domain's workflow board: the surface, the version, the Project Context and, in Claude Code, the state of the working-folder guard and its manifest. `/bandit:audit` scores a domain from those stamps and the boards (snapshot schema 8); a domain is a top-level board folder. A board no stamp names is unchecked and says so.
- **One configuration per project.** `bandit:project` works on the surface the chat runs on: in Claude Code it reads the folder's `CLAUDE.md` and `.claude/`, says whether the project is a workflow agent or a technical one, checks it is ready for Bandit Brain, and proposes every change as a row; a file is written only for an approved row, with a way back first. On Claude.ai the instructions are handed over to paste. It never writes the user's own settings and never removes a permission rule or a hook.
- **Two reference notes.** The reference doc is the note `{slug}-reference` on the project's board; a Claude.ai project's instructions also get a copy, `{slug}-instructions`. One note each, updated in place.
- **Taking a card.** `bandit:tasks`: a card taken to work on gets today's date when it has none, and follows the work in Execution (Doing, Stand By, complete). `/bandit:tasks doing` sets the date in the same step.
- **`/bandit:notes lint` checks names and the hub note:** a title that breaks conventions §4, two notes with one title in one place, a project board with no hub note or with two, customer data in a note's text.

### Changed
- **A marketplace card is saved on the marketplace project's own board** (BM-T5). `bandit:clarify` and the sprint release no longer name a Marketplace column: the card goes to the board the marketplace project's `board:` line names, which is now BB: Marketplace.
- **The audit runs the rows it can reach.** A row that changes another project's instructions or folder is handed over as one line saying where to run what; a project changes only itself. Rules S1, S2, S4, S6, S12 and S13 are restated on the stamp; S4 accepts `notes: none`. Checker rules A1 and A2 follow (a fixture per kept rule, an old snapshot refused by name).
- **The working-folder layout allows `REFERENCE.md`** at the root, for a project with `notes: none`, and its rollback copy in `_backup/`.
- **A finished card's conclusions are written on every project**, except one whose Project Context says `notes: none`.
- **A project's notes are in the app's Notes unless its Project Context says `notes: none`.** A missing `notes:` line used to mean the MyNotes vault; it now means the app. `notes: app`, written before this version, stays valid and says the same thing. `notes: none` is new: the helpers write no note for that project. Checker rule AT2 accepts `none` and `app` and refuses any other value.
- **The instruction templates no longer start with a settings line.** The comment on line 1 named a vault settings folder; a project now has one instructions file and no second copy to track. The `dev` template describes a project that runs in Claude Code from capture to close.
- **The sprint helper runs on the app's waves, pause, replan and cancel** (BM-22). This needs the Bandit Brain app 0.56.0 or later. Planning now puts each card in its wave in the app itself, writes the plan's "lands after" pairs as real links, and puts the debug card alone in a last wave so the waves of work can finish without it. A wave reads its cards and the sprint's run state from the app and stops on a paused or replanning sprint. When work stops on your answer and nothing else can run, the sprint is paused in the app with your question as the reason, and resumed once you answer. Close takes a card that stays open out of a sprint in debugging without being refused, and closes it as before. A cancelled sprint counts as closed. Asking for a "lands after" link no longer asks for a gate sub-task.
- **The sprint map page is gone; the app draws the map** (BM-22). Each wave's time estimate now goes in the plan's wave table, and the sprint's total in the first line of the planning report. Checker rules SM1 and SP12 are retired; new rule WV1 tests the waves work.
- **The board helper knows the app's waves, lands-after links, pause, replan and cancel** (BM-21). This needs the Bandit Brain app 0.56.0 or later for sprints. The helper's table of the app's refusals now covers a cancelled sprint, a change to a running sprint made without your confirmation, a card in the wrong wave, a wave that still holds cards and a pause or cancel with no reason; it also corrects folders, which nest three levels deep. Its board rules say what waves and the run state are, and how a "lands after" link orders two cards without blocking either. The repo checker now reads the app at 0.56.0, and new rule ER1 fails when the app's tools name a refusal the table has no row for.

### Fixed
- **The sprint check at the end of a reply runs only in a sprint chat** (BM-19). It used to treat every chat of a dev repository as a sprint chat, because the skill and agent lists name the sprint helper, so an ordinary chat ended each reply with a notice about an old notes file. It now runs only when the chat called the sprint helper, you typed `/bandit-dev:sprint`, or a tool built, read or checked the notes file. Checker rule SP8 tests a chat that holds only the lists.
- **The sprint checker accepts a closed sprint whose plan stays Done with its card** (BM-20). The app keeps a plan linked to a card at that card's state and will not archive it, so a closed sprint with such a plan no longer fails SP15; any other paper left unarchived still does. A closed sprint's plan is no longer read for work owed (SP14). A paper without its sprint's tag, and a sprint tag on notes when that sprint has no papers, are each named in one plain line instead of a list of missing papers. The notes file's build rule now reads every sprint's papers in full, copies tags as they are stored and sorts what it writes, so two builds of the same notes give the same file. Checker rules SP14, SP15 and NF1 test it.
